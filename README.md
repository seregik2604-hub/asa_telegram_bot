# ASA Telegram Trading Bot

Бот принимает алерты стратегии из TradingView (вебхук), фильтрует их по
RR, ведёт журнал сделок и показывает статистику в Telegram.

## Почему агент торговал в минус: диагноз

Проведён полный чекап (июнь 2026). Найдено и исправлено:

### 1. Приложение вообще не работало
В `main.py` и `wsgi.py` при копировании кода из чата попали куски
markdown-текста (```` ``` ````, «Нажми Commit changes» и т.д.).
Это давало `SyntaxError` — **сервер падал при старте**, сигналы не
доходили, журнал не вёлся. Исправлено.

### 2. Результаты сделок не записывались
Запрос `UPDATE ... ORDER BY ... LIMIT 1` не поддерживается в большинстве
сборок SQLite — закрытие сделок (TP/SL) молча падало, поэтому
винрейт в `/stats` всегда был пустой/нулевой. Переписано через подзапрос.

### 3. Не было фильтра RR
Бот пересылал любой сигнал. Теперь RR **пересчитывается на сервере**
из реальных Entry/SL/TP (значению из алерта не доверяем), и сигналы с
RR < 2 отклоняются (порог — переменная окружения `MIN_RR`, по умолчанию 2.0).

### 4. Неправильный расчёт пипсов
`* 10000` неверно для JPY-пар (нужно ×100), золота и крипты.
Теперь размер пипса определяется по символу.

### 5. База стиралась при каждом деплое
На Heroku/Render файловая система эфемерная — `trades.db` обнулялась
при рестарте. Задайте `DB_PATH` на постоянный диск (Render Disk,
Railway Volume): `DB_PATH=/data/trades.db`.

## Главный вывод по прибыльности (важно!)

Сама торговая логика живёт не в этом репозитории, а в Pine Script на
TradingView. Чтобы найти прибыльную конфигурацию, был собран бектест на
6 годах данных EURUSD H1 (2016–2021, данные:
[FX-Data](https://github.com/FX-Data/FX-Data-EURUSD-DS), движок:
[backtesting.py](https://github.com/kernc/backtesting.py)).

Протестировано 24+ конфигураций классических SMC-входов (откат к EMA +
поглощение, генерический liquidity sweep, пробой Donchian на H4) — **все
убыточны** (PF 0.69–0.97). Подгонка параметров на 2016–2019 давала
PF до 1.47, но на out-of-sample 2020–2021 все «лучшие» параметры
проваливались — это оверфиттинг, а не преимущество.

Единственная модель с устойчивым плюсом на полном периоде —
**свип азиатской ликвидности в лондонский killzone** (ICT Judas Swing)
с фильтром displacement:

| Метрика | Значение (EURUSD H1, 2016–2021) |
|---|---|
| Профит-фактор | **1.31** |
| Винрейт | 37.3% при RR 1:2 (безубыток = 33.4%) |
| Сделок | 158 (~2/месяц — это нормально) |
| Макс. просадка | −4.1% |

Готовая стратегия: [`pine/asa_sweep_strategy.pine`](pine/asa_sweep_strategy.pine) —
вставьте в TradingView, прогоните Strategy Tester на своём инструменте,
подключите алерты к вебхуку бота.

**Честное предупреждение:** на отрезке 2020–2021 отдельно PF ≈ 1.0.
Никакие параметры не гарантируют плюс в будущем. Что реально держит
вас в плюсе при RR ≥ 2:
1. Не входить без сетапа (фильтр бота теперь отклоняет RR < 2 за вас);
2. Торговать только killzone-сессии (Лондон/НЙ) — вне их у моделей нет преимущества;
3. Вести журнал и раз в месяц смотреть `/breakdown` — отключать связки
   (пара/сессия/POI), которые стабильно минусуют;
4. Риск ≤ 1% на сделку — при RR 2 и винрейте 35% бывают серии из 8+ стопов.

## Математика RR (зачем минимум 1:2)

| RR | Винрейт безубытка | Ваша цель |
|---|---|---|
| 1:1 | 50% | 55%+ |
| 1:2 | 33.4% | 38%+ |
| 1:3 | 25% | 30%+ |

## Команды бота

- `/stats` — винрейт, PnL, профит-фактор, expectancy, сколько сигналов отфильтровано
- `/breakdown` — разбивка по парам, сессиям, H1/H4 POI

## Бектест

```bash
pip install -r backtest/requirements.txt
python backtest/asa_backtest.py                          # модель sweep, дефолты
python backtest/asa_backtest.py --strategy pullback      # старая модель (убыточна)
python backtest/asa_backtest.py --optimize --split 2020-01-01   # walk-forward
python backtest/asa_backtest.py --symbol GBPUSD --source fxdata
```

`--split` обязателен при оптимизации: параметры подбираются до даты,
проверяются после. Без этого результат — подгонка под историю.

## Переменные окружения

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | токен Telegram-бота |
| `CHAT_ID` | чат для сигналов |
| `MIN_RR` | минимальный RR (default 2.0) |
| `DB_PATH` | путь к базе (поставьте на постоянный диск!) |
